## 2. 수정 전 문제

리뷰 문서 #6. 계획서 §61 이 요구하는 3개 베이스라인 중 **B(Carrier Separate)가 없었습니다.**
§62 의 핵심 비교 KPI 는 B vs C 이므로, AXIS 의 핵심 가치 명제

> 개별 선사 단위로는 철도화하기 어려운 소규모 공컨 이동수요를
> 복수 선사 수요 통합으로 철도 대량수송 수요로 전환한다

를 **정량적으로 증명할 수 없었습니다.** "통합했더니 2편"만 있고 "통합 안 하면 몇 편"이 없었습니다.

---

## 3. 구현 방식

### 동일 조건 보장 (지시서 요구)

세 시나리오가 아래를 **완전히 동일하게** 사용합니다.

```
service need         동일한 generate_service_needs() 결과 1개를 공유
candidate timetable  동일한 MODEL_INPUTS
formation option     F33 / F40 / (경부축 F50)
minimum load factor  0.5
max earliness        72h
handling time        상차 3h / 중간 3h / 하화 3h
운영 가정             동일 (편도, 회송 미포함)
```

`run_baselines()` 가 시작 시 `configure_params()` 를 한 번만 호출해 세 시나리오가
같은 파라미터 인스턴스를 쓰도록 했습니다.

### B 구현

동일한 need 집합을 유지한 채 **carrier 단위로 MILP 를 따로 풀고 합산**합니다.

```python
meta, lo, up, integ = m.build_milp(service, trains, min_lf, None, None,
                                   "PROPOSAL", {}, max_earliness, {c})   # carrier_subset={c}
```

각 선사가 자기 열차만 쓰므로 **열차 공유가 원천적으로 불가능**합니다.

> 지시서 명시사항: **B 가 0편이 나오도록 모델을 조정하지 않았습니다.**
> 실제로 B 는 0편이 아니라 1편이 나왔습니다 (§4).

## 5. 해석

### 5-1. B 는 0편이 아니다

**CARRIER_A 는 단독으로도 열차 1편을 운행할 수 있습니다.**
부산신항→약목(경부축 상행) 단일구간이며, A 의 구조적 재배치 축(supply_base=BUSAN,
demand_base=YAKMOK)과 정확히 일치합니다. A 는 주간 67 TEU 의 need 를 갖고 있어
143.7km 단일구간 열차의 50% 적재(33 TEU)를 혼자 채울 수 있습니다.

나머지 5개 선사는 **실행가능 assignment 가 0**입니다. 시간창 안에서 어떤 후보열차도
최소 consolidation 요건을 만족시키지 못합니다.

> 이 결과가 오히려 **더 설득력 있습니다.** "통합 없이는 아무것도 안 된다"보다
> "가장 큰 선사 하나만 겨우 단거리 1편이 가능하고, 나머지 5개 선사는 전혀 불가능하다"가
> 실제 시장 구조에 가깝고 방어하기도 쉽습니다.

### 5-2. 통합 효과

| 지표 | B → C |
|---|---|
| 서비스 물량 | 34 → 138 TEU (**4.06배**) |
| TEU-km | 4,886 → 33,802 (**6.92배**) |
| 미충족 | 146 → 42 TEU (**71% 감소**) |
| 편당 참여선사 | 1.0 → **4.0** |
| 철도운임 수입 | 164만 → **1,224만원 (7.45배)** |

**핵심:** 열차 수는 1 → 3편으로 3배 늘었는데 TEU-km 는 6.9배, 수입은 7.5배 늘었습니다.
통합이 단순히 열차를 더 띄우는 것이 아니라 **같은 열차에 더 많은 선사 물량을 실어
장거리 다구간 서비스를 가능하게 만든다**는 뜻입니다.

B 의 유일한 열차는 143.7km 단일구간인 반면, C 의 열차는
`의왕→부강→약목→부산신항`(408km, 5개 선사), `의왕→부강→동산→신광양항`(391km, 6개 선사)
같은 다구간 서비스입니다.

### 5-3. A 의 의미

철도 재배치가 없으면 180 TEU 의 Service Need 가 전량 미충족입니다.
`BASELINE_NO_REPOSITIONING.csv` 에 부족 발생 시점·거점이 기록되어 있습니다.

## 6. Others pool 관련 보수적 가정 (재확인)

`CARRIER_F` 는 계획서 §13 의 "Others" — 공개자료 상위 5사를 제외한 **다수 소형선사의 풀**입니다.
이를 단일 carrier 로 취급하면 B 에서 그 풀이 뭉쳐진 물량으로 열차를 띄울 수 있으므로
**B 가 실제보다 유리해집니다.** 즉 AXIS 통합효과를 과대평가하지 않는 방향입니다.

(실제로는 F 도 0편이었으므로 이번 결과에서는 영향이 없었습니다.)

## 8. 작업 중 수정한 문제 2건

### 8-1. FINAL 에서 후보 0 을 오류로 처리하던 문제

`FINAL_MIXED` 처럼 확정 물량이 적어 후보열차가 0 이 되면
Phase 8 에서 도입한 `NO_FEASIBLE_RAIL_SERVICE` 구조화 오류가 발생해 파이프라인이 중단됐습니다.

그러나 **FINAL 에서 0편은 정상 결과**입니다. 오류가 아니라 "확정 물량이 최소 consolidation
요건에 못 미쳐 전용열차를 운행하지 않는다"는 서비스 원칙의 직접적 표현입니다.
FINAL 모드에서는 예외를 던지지 않고 정상 출력을 내도록 수정했습니다.

### 8-2. 베이스라인 러너가 파라미터를 로드하지 않던 문제

`axis_baselines_v7.py` 가 `configure_params()` 를 호출하지 않아
`SEGMENT_DISTANCE` 가 비어 `KeyError` 가 발생했습니다.
러너 시작 시 1회 호출하도록 수정했으며, 이로써 **세 시나리오가 같은 파라미터를 쓴다는 것이
코드 수준에서 보장**됩니다.

## 9. 남아있는 한계

1. **B 는 "각 선사가 독립적으로 KORAIL 전용열차를 발주한다"는 가정**입니다.
   실제로는 기존 정기열차 잔여공간 이용, 트럭 전환 등 다른 선택지가 있습니다.
   프로젝트 전제(§2.1 기존 열차 잔여공간 미사용)에 따른 비교입니다.
2. **단일 주간(2026-08-10~16) 결과**입니다. 다른 주차에서는 B 의 열차 수가 달라질 수 있습니다.
3. B 의 합산 KPI 는 선사별 최적해의 단순 합입니다. 선사 간 상호작용은 정의상 없습니다.
4. 수익성 비교가 아닙니다. `expected_korail_revenue_krw` 는 **tariff 기반 예상 수입**이며
   운영원가를 차감하지 않았습니다.
5. 화차 회송이 포함되지 않은 편도 기준입니다 (A/B/C 모두 동일 조건이므로 비교에는 영향 없음).
